Arquitectura C++ Asíncrona:
Clúster de Reportes, AI Semántica (LLM) y Enrutamiento ETL

Especificación de ingeniería pura centrada en cómo el motor de lenguaje principal (C++) recibe, manipula y transforma la carga transaccional del editor "TipTap" y de los módulos cartográficos. Se ilustran las pasarelas WSS de cámaras nativas (Surveillance), el pipeline concurrente ortográfico conectado al LLM (Ollama) local, y el bridging intensivo de métricas KPI a PostgreSQL 15 a velocidad RAM.

1. Mapeo de Clases y Puertos de Rutas API (Crow)

El backend elimina el overhead de lenguajes interpretados usando macros directos CROW_ROUTE y la librería Crow incrustada bajo el contexto asíncrono de Boost.Asio. Aísla las funcionalidades del informe técnico en rutas de rápida asimilación de cadenas JSON dinámicas (`crow::json::rvalue`).

Manejo de Transacciones LibPQ (Inyección Directa)

En el C++ ignoramos capas ORM (Object-Relational Mapping). Emplear punteros Pq_execParams evita que el backend despilfarre ciclos de CPU intentando descifrar el masivo e interminable DOM JSON del editor TipTap. Simplemente lo aseguramos (String Sanity), abrimos una transacción asíncrona ACID, se impacta la DB y cerramos (Connection Release).

Bypass de Bloqueos en Múltiples Operadores

La vista dinámica usa UUID V4s de forma exigente. La concurrencia asíncrona se rige usando punteros seguros y los middlewares custom de comprobación (extracción JWT / tenant_id por Header) antes de permitir accesos CRUD sobre los informes bloqueados.

2. Pipeline Funcional de Procesamiento Semántico L.L.M.

El C++ asume la labor de orquestador transicional. Cuando un autor en ControlTime decide auditar sintaxis geomecánica, el backend enruta el payload al componente especializado (text_spell_service.cpp) a través de peticiones HTTP locales encapsuladas sobre hilos que no detengan el WebSocket ni el Gateway Minero.

Mecánica de Tiempo de Expiración (Timeout Resiliency):

Las redes neuronales (LLMs) son propensas a latencias extremas. El backend C++ implementa colapsos (Timeouts) restrictivos usando Boost.Asio timers. Si Ollama no reporta el primer vector en el gAiEngineTimeoutMs (configurable en variables de entorno), el sistema emite un Fast-Fail HTTP 504 Gateway Timeout directo a React; impidiendo un Thread Lock (Bloqueo de Hilos) que tumbaría los sockets de telemetría de toda la mina.

3. Proxy de Agregación ETL In-Memoria (CCTV & KPIs Dinámicos)

Se diseñó al motor C++ como un "Proxy Paralelo". El informe llama al Endpoint de reportes estáticos, pero la página incrusta KPIs vivos (Ej. Dashboards de Aceleración); el C++ captura estas llamadas, cruza hipertablas e incrusta flujos HTTP de FFMPEG al vuelo para el CCTV.

Agrupamiento Nativo de Series Temporales (Time-Buckets)

Las consultas /api/mining/kpis/points solicitadas por el editor del informe (para pintar áreas de sensores Inclinómetros) envían fechas límite. El C++ utiliza la directriz time_bucket() nativa de TimescaleDB al concatenar su string LibPQ SQL. En memoria de C++ convergen agrupamientos minificados (MinMax) reduciendo 1,000,000 de registros telemétricos a los 300 puntos exactos que necesita la librería gráfica en React, abaratando severamente los costos de ancho de banda (Egress) corporativos.
