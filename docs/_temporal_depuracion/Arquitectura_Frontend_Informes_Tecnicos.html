Arquitectura Visual del Motor Base:
Generador de Informes Técnicos Interactivos

Especificación de ultra-alta fidelidad sobre el módulo ReportStudioV2 (Informes Técnicos). Disecciona cómo el árbol DOM de React 18 acopla motores de texto sin cabeza (TipTap/ProseMirror), inyecta interactividad inteligente a sub-nodos (corrección semántica LLM y CCTV en línea), maneja ciclos de re-renderizado protegidos (Zustand) y domina el envenenamiento criptográfico-biométrico (Modal WebRTC) para estampar firmas de aprobación ICAO indisolubles.

1. Topología del Virtual DOM: Motor Headless TipTap

El Reportador Técnico repudia componentes cerrados de texto estáticos. Instanciamos TipTap (basado en ProseMirror), un core "Headless", al que empalmamos Nodos de React (`NodeViews`) altamente modificados. Un informe es tratado como un objeto JSON unificado interactivo, no como un bloque HTML crudo.

Manejo de Estado Desacoplado (Zustand & Debounce)

En el editor, las pulsaciones alcanzan frecuencias inmensas (60+ wpm). Desatar un re-render del árbol React global por cada tecla colapsaría la memoria del navegador. Empleamos un store atómico temporal en el useEditor hook que solo dispara la señal de Auto-Guardado a Backend empaquetando el JSON resultante tras 1,500ms de inactividad (Lodash Debounce).

El Nodo de IA (BubbleMenu Overlays)

Cuando el operador selecciona una frase para reescribir con LLaMa-3, la extensión de Tiptap intercepta el cruce de ejes X/Y en la pantalla nativa y renderiza un menú flotante en CSS usando cordenadas absolutas fijadas a la selección del texto interactivo, manteniendo en primer plano los inputs ortográficos sugeridos sin mutar el formato general del documento.

3. Máquina de Autorizaciones Biométricas (Security Shield)

La interacción humana con un documento corporativo es inamovible en base a sus etiquetas de custodia. Se implementó una bóveda de protección React a nivel de componente (`Permissions Props`) atada a los estados formales exigidos (FSM) que controla la visualización del modal biométrico de ICAO.

title Frontend Security Bounds: Workflow de Aprobación y Modal Biométrico (WebRTC)

[*] --> Estado_Borrador : Creado por Ing.

state Estado_Borrador {
  [*] -> Editor_Activo
  Editor_Activo : "editable = true" en Instancia TipTap
  Editor_Activo : "Botones Toolbar" = Habilitados
}

Estado_Borrador --> Estado_Pendiente : Acción Usuario: Clic en "Enviar Aprobación"

state Estado_Pendiente {
  [*] -> Editor_Bloqueado
  Editor_Bloqueado : "editable = false"
  Editor_Bloqueado : "Botones Toolbar" = Deshabilitados visualmente ("Opacity: 50%")
  Editor_Bloqueado -> Modal_Firma_WebRTC : Al dar CLIC: "Aprobar Informe Final"

state Modal_Firma_WebRTC {
  [*] -> Activar_Ref_Video
  Activar_Ref_Video : React usa "navigator.mediaDevices"\npara renderizar elemento de video nativo
  
  Activar_Ref_Video -> Extraccion_Frames_Ovalo
  Extraccion_Frames_Ovalo : 1. Pinta CSS Bounding Oval (Centro)
  Extraccion_Frames_Ovalo : 2. Convierte canvas de video al vuelo
  
  Extraccion_Frames_Ovalo -> Post_Biometria
  Post_Biometria : Emite frame codificado HTTP hacia Backend (C++)
}

Modal_Firma_WebRTC --> Error_UI_Feedback : Rechazo de AI Backend (Liveness Fail)
Error_UI_Feedback --> Activar_Ref_Video : Reintentar Proceso en UI RAM

Modal_Firma_WebRTC --> Estado_Aprobado : Confirmación Biometría (Match Cripto)

state Estado_Aprobado {
  [*] -> Editor_Sellado
  Editor_Sellado : Banner Superior Notificativo: "Sello Cripto Valido"
  Editor_Sellado : Reporte Congelado 100% Permanente. Impide edición total a Admins.
}

Estado_Aprobado --> [*] : Cierre.

@enduml

Control de Bloqueo a Nivel Componente C.R.U.D

El Frontend es inclemente con la falsificación de estados. Para evitar que un usuario manipule el LocalStorage (forzando editable=true), el componente ReportStudioWrapper observa continuamente la variable report.status sincronizada desde el backend. Si el estado es distinto de "DRAFT" o si el usuario activo no posee rango de jerarquía USER_ROLES contra el autor, las barras de herramientas (Toolbars), los atajos (CTRL+B, CTRL+Z) y las rutinas de Red interna de guardado se bloquean permanentemente en memoria, evitando de tajo que se corrompa el hash de integridad documental antes de llegar a la base de datos.
