1. Persistencia Documental: Estructuras y Entidad-Relación

El núcleo del ReportStudioV2 repulsa las tecnologías antiguas estáticas (PDF/DOCX) hacia un esquema nativo transaccional JSONB (Document Store). Esto permite consultas ultra rápidas, fragmentación del documento para firmas, incrustación de gráficos IOT vivos y control auditable línea por línea dentro de Postgres.

Indexado & Búsqueda Semántica Vectorial

Al guardar el contenido en un campo nativo PostgreSQL JSONB, habilitamos índices invertidos GIN (`CREATE INDEX ON reports USING GIN (content_state)`). Todo el informe es rastreable y minable a la perfección de forma online sin exportación pre-cálculo.

Aislamiento Absoluto (Multi-Tenant RLS)

Las consultas están envueltas en el Row Level Security (RLS) en cascada hacia el tenant_id. Un gerente en la sede de operaciones mineras en EE. UU. (Tenant A) no colisionará con los reportes de supervisión de la operación de Perú (Tenant B).

2. Flujo de Autorización, Firmas Biométricas y Despacho Físico

Un informe técnico redactado y minado posee implicaciones corporativas y legales. Modelamos un WorkFlow FSM (Finite State Machine) con Firma y Contrafirma condicionada a Validación Biométrica Liveness.

@startuml
skinparam DefaultFontName "Inter"
skinparam sequenceMessageAlign center
skinparam sequence {
    LifeLineBorderColor #334155
    BoxBackgroundColor #F8FAFC
}

title Ciclo Operacional: Creación, Firma Biométrica y Handover de Informes Técnicos

actor "Ing. Geomecánico\n(Autor)" as ING
box "C++ Backend & AI Engine" #FEF3C7
participant "Spell Checker\n(Ollama AI / LT)" as OLL
participant "Mining Gateway\n(Transaccional)" as API
participant "AI Biometrics\n(MediaPipe/InsightFace)" as ICAO
end box
database "PostgreSQL 15 + Outbox" as DB
actor "Gerente Operaciones\n(Aprobador)" as GER

== Fase 1: Redacción Híbrida y Corrección AI ==
ING -> API : POST /api/text/rewrite\n(Párrafo borrador de rocas)
activate API
API -> OLL : Ejecutar Ollama Llama3 / LanguageTool (Corrección)
OLL -->> API : Párrafo corregido geológicamente
API -->> ING : Actualiza "Editor TipTap" UI
deactivate API

ING -> API : SAVE (Action: DRAFT_SAVE)\n{ content_state_jsonb }
activate API
API -> DB : update_modified_column() + UPSERT en `reports`
DB -->> API : OK
deactivate API

== Fase 2: Solicitud de Aprobación Oficial ==
ING -> API : POST /api/reports/{id}/finalize\nRole: Ing. Geomecánico
activate API
API -> DB : UPDATE `authz_workflow` SET state='PENDING_REVIEW'
API -> DB : TRG: `trg_alerts_after_insert_fanout()`\nInyecta Mensaje Revisión
DB -> DB : INSERT `org_notification_outbox` (To: Gerente_Email)
API -->> ING : "Bloqueo de Edición (Readonly)"
deactivate API

== Fase 3: Aprobación Gerencial (Firma Geométrica Doble) ==
GER -> API : Solicitud GET /api/reports/{id}
API -->> GER : Carga Visor Lectura
GER -> API : POST /api/reports/{id}/approve (Requiere Biometría)
activate API

API -> ICAO : /analyze_eyes + /face_embedding\n(Stream Webcam del Gerente)
activate ICAO
note left of ICAO: Se valida "Proof of Life" (anti-spoof),\nMismatches bloquean Criptografía.
ICAO -->> API : 100% Match (Biometric ID Logged)
deactivate ICAO

API -> DB : UPDATE `authz_workflow` SET state='APPROVED'\nbiometric_log_id = 
API -> DB : INSERT `platform_audit_log` (Firma Criptográfica)
DB -> DB : TRG FanOut SMS: Informe Distribuido Oficialmente.
API -->> GER : 200 OK - Sello Notariado.
deactivate API

@enduml

Exclusión de Manipulación y WatchDog (Seguridad Estricta):

  • trg_fn_auth_audit_security_after_insert(): Durante la Fase 3, si la red neuro-biométrica rechaza el rostro del supuesto Gerente (Liveness Fail o Falso Rostro), este trigger intercepta el intento de fraude directamente en el clúster de Base de Datos y lanza alertas silenciosas al departamento IT encolándose en org_notification_outbox.
  • Bloqueo C.R.U.D Invariable: Una vez que la máquina de estados authz_workflow avanza a "PENDING_REVIEW", el sistema cancela los comandos de UPSERT del editor anulando los accesos a la API transacciona.

3. El Paradigma de Informes "Live" (Online ETL Engine)

Los Informes Técnicos de ControlTime no son "Fotos del Pasado" inertes. Son aplicaciones integradas incrustadas. Cuando se arrastra un gráfico IoT o se agrega un KPI tabular a la hoja web, el reporte no almacena PNGs; almacena las referencias sintácticas al ETL Data Fetcher.

@startuml
skinparam DefaultFontName "Inter"
skinparam componentStyle rectangle

title Diagrama de Componentes: Reportería Live (ETL Queries en vuelo)

node "Visor Frontend (TipTap React UI)" as UI {
    [Bloq. Texto HMTL]
    [Bloq. **Live Widget KPI**] as WIDGET
    [Bloq. **CCTV Snippet**] as VIDEO
}

package "API Gateway (C++)" {
    component "Report Parser Engine" as PARSER
    component "ETL Connector" as ETL
}

database "T.S. DB" {
    [Telemetría RAW\n(Chunks)] as RAW
}
database "External SCADA" {
    [KPI Master DB] as EXT
}

WIDGET --> PARSER : Request `sensor_id`, Rango Fechas
PARSER --> ETL : Construir Query Agregada

ETL -left-> RAW : Fetch Mín/Max/Avg (TimescaleDB)
ETL -right-> EXT : Call ODB/API Proxy\n(Si es KPI Externo Integrado)

ETL --> PARSER : Combina Dataset
PARSER --> WIDGET : Devuelve Array de Datos puros
WIDGET -> WIDGET : Renderiza Chart interactivo al momento de lectura

note bottom of WIDGET
    Rehidratación de Datos Analíticos (Online ETL)
    Al abrir el informe, las tablas/dashboards
    realizan un PULL de los datos. Permite 
    visualizar tendencias dinámicas. Si un reporte
    debe "congelarse", se archiva en PDF o
    en metadato estático encapsulado por el API.
end note

@enduml

Sincronización Periférica en Reportes

Mediante el sistema distribuido, un vídeo (o CCTV en loop) incrustado apunta a la ubicación en el sub-sistema base report_media_assets. Si el operario necesita demostrar geomecánica, adjunta un fragmento `.mp4` el cual es parseado por la arquitectura y conservado fuera de los esquemas transaccionales relacionales para no paralizar los SSD del TimescaleDB.

Buses ETL Asíncronos Integrados

Usando Jobs agendados en `etl_job_definition` controlados por pg_cron local o workers C++, la base de datos importa resúmenes agregados (Ej. Producción Camiones vs Tiempos Muertos) directo desde las fábricas de TI externas, permitiendo incrustar dicha matemática "Masticada" dentro del reporte sin afectar latencias Frontend.
