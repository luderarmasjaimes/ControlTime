Para usar sensores reales del celular (GPS, acelerómetro) hace falta HTTPS (iniciar-pagina-prueba-https.bat, puerto 5443) — los navegadores móviles no exponen esas APIs fuera de un contexto seguro.

1. Iniciar sesión se necesita rol admin/manager

Se necesita el permiso dispositivos.manage (roles admin/manager) solo para registrar el sensor una vez (paso 2). Enviar lecturas (paso 4) no usa esta sesión — usa la API key del dispositivo.

"Aceptadas" = HTTP 202 de POST /api/mining/telemetry (la lectura ya quedó encolada en TelemetryIngestor, no implica todavía que el flush a la base de datos haya corrido — el flusher trabaja por lotes cada ~200ms). En Android Chrome, devicemotion/ deviceorientation no piden permiso explícito (basta HTTPS); en iOS Safari sí — use el botón "Permitir sensores" antes de iniciar.

5. Verificar que llegó

Consulta GET /api/mining/devices (con la sesión del paso 1) y muestra connection_status/last_seen_at del sensor activo — pasa a online apenas la primera lectura HTTP es aceptada. Para ver la serie completa, use el panel real (Dashboard/ReportStudio → bloque de sensor) o GET /api/mining/telemetry/wizard/query?sensor_ids=... con la sesión.
