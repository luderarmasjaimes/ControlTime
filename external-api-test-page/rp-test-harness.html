0. Configuración requerido primero

Esta página se sirve intencionalmente en un origen distinto al del backend, simulando una aplicación externa real. Si el backend rechaza las peticiones, agregue el origen exacto de esta página (visible arriba en origin) a BEEMETRY_CORS_ALLOWED_ORIGIN del backend. Ver docs/integration/RP_TIMETELEMETRY_API_GUIDE.md para el contrato completo de esta API, y docs/integration/EXTERNAL_API_TEST_PAGE.md para cómo servir esta página.

1. Sesión POST /api/auth/login/password

El usuario necesita el permiso rp.equipment.view (lectura) y/o rp.equipment.edit (escritura) en su tenant — ver RP_TIMETELEMETRY_API_GUIDE.md §4.

2. Tiempo real WS /ws?auth_token=…

Requiere sesión activa (sección 1). Recibe {"channel":"rp","type":"rp_equipment_updated", "equipment_id":"…"} cada vez que un equipo de su tenant se sincroniza (alta, edición, o cambio traído desde TimeTelemetry).

3. Lista de equipos GET /api/rp/equipment

Lee de la réplica local — no depende de que TimeTelemetry esté disponible en el momento de la consulta.

4. Detalle y estado de sync GET /api/rp/equipment/{id}[/sync-status]

5. Crear equipo POST /api/rp/equipment

Respuesta 202 = aceptado localmente, aún no confirmado en TimeTelemetry — use la sección 4 (sync-status) o la sección 2 (WebSocket) para saber cuándo queda synced. El equipment_id devuelto se copia automáticamente al campo de la sección 4.

6. Actualizar equipo PUT /api/rp/equipment/{id}

409 not_yet_synced es la respuesta esperada si intenta editar un equipo recién creado que todavía no tiene external_id real de Odoo.

7. Log de peticiones/respuestas REST

Herramienta de pruebas — no usar credenciales productivas reales. Contrato completo en docs/integration/RP_TIMETELEMETRY_API_GUIDE.md.
